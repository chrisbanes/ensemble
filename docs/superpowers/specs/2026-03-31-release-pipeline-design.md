# Release Pipeline Design

## Overview

Automated release pipeline for Ensemble, distributing the CLI binary and Tauri desktop app via GitHub Releases and Homebrew.

## Goals

- One-command release workflow (`cargo release <version> --execute`)
- Consistent version number across all artifacts
- Prebuilt binaries for CLI (no source compilation on user machines)
- Signed + notarized macOS desktop app
- Automated Homebrew tap updates at `chrisbanes/homebrew-tap`

## Artifacts

| Artifact | Targets | Distribution |
|---|---|---|
| `ensemble` CLI binary | macOS aarch64, Linux x86_64, Linux aarch64 | GitHub Release + `brew install chrisbanes/tap/ensemble` |
| `Ensemble.dmg` desktop app | macOS aarch64 | GitHub Release + `brew install --cask chrisbanes/tap/ensemble-desktop` |

**Not in scope:** crates.io publishing, Windows builds, Linux desktop app, macOS Intel builds.

## Version Management

### Single source of truth

The workspace-level version in the root `Cargo.toml`:

```toml
[workspace.package]
version = "0.1.0"
```

All crates inherit with `version.workspace = true`. The `tauri.conf.json` version is kept in sync by a `cargo-release` pre-release hook.

### Bumping workflow

```sh
cargo release 0.2.0 --execute
```

This:
1. Updates `version` in root `Cargo.toml` (all crates inherit it)
2. Runs a pre-release hook to update `crates/ensemble-desktop/tauri.conf.json`
3. Commits as `release: v0.2.0`
4. Creates git tag `v0.2.0`
5. Pushes commit + tag

### cargo-release configuration

A `release.toml` at the workspace root:
- Shared version mode (all crates share one version)
- Tag format: `v{{version}}`
- Pre-release replacements: regex-update `"version"` in `tauri.conf.json`
- `publish = false` for all crates (no crates.io)
- Commit message template: `release: v{{version}}`

## CI Release Workflow

**Trigger:** Push of a tag matching `v*`.

**File:** `.github/workflows/release.yml`

### Phase 1: Build CLI with cargo-dist (3 targets)

[cargo-dist](https://opensource.axo.dev/cargo-dist/) handles cross-compilation, GitHub Release creation, and Homebrew formula generation.

**Targets:**
- `aarch64-apple-darwin`
- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`

**Custom build step:** Before each Rust build, the SPA must be embedded:
1. Install pnpm + Node 22
2. `pnpm install --frozen-lockfile` (in `crates/ensemble-ui/src-ui/`)
3. `pnpm run codegen` (OpenAPI spec generation + client)
4. `pnpm run build:embed` (Vite build to the embed output directory)

cargo-dist supports custom build steps via `dist.toml` (or `Cargo.toml` metadata). The SPA pipeline runs as a `pre-build` step.

**Outputs:**
- Tarballs per target uploaded to GitHub Release
- SHA256 checksums
- Homebrew formula auto-pushed to `chrisbanes/homebrew-tap/Formula/ensemble.rb`

### Phase 2: Build Desktop with Tauri Action (parallel with Phase 1)

Uses `tauri-apps/tauri-action` for the macOS aarch64 build.

**Steps:**
1. Build the frontend (same SPA pipeline as Phase 1)
2. Run Tauri Action with signing + notarization enabled
3. Upload `.dmg` to the same GitHub Release

**macOS signing and notarization** via Tauri Action environment variables:
- `APPLE_CERTIFICATE` — base64-encoded .p12 signing certificate
- `APPLE_CERTIFICATE_PASSWORD` — certificate password
- `APPLE_ID` — Apple ID email
- `APPLE_TEAM_ID` — Apple Developer team ID
- `APPLE_PASSWORD` — app-specific password for notarization

**Runner:** `macos-latest` (ARM runner for native aarch64 build)

### Phase 3: Update Homebrew Cask (depends on Phase 2)

After the Tauri build uploads the `.dmg`:
1. Download the `.dmg` from the GitHub Release
2. Compute SHA256
3. Generate/update `Casks/ensemble-desktop.rb` in `chrisbanes/homebrew-tap`
4. Push via `HOMEBREW_TAP_TOKEN` (GitHub PAT with repo access to the tap)

## Homebrew Tap Structure

Repository: `chrisbanes/homebrew-tap`

### Formula: `Formula/ensemble.rb`

Auto-generated by cargo-dist. Installs prebuilt CLI binary. Updated automatically on each release.

```ruby
class Ensemble < Formula
  desc "Multi-agent pipeline orchestrator"
  homepage "https://github.com/chrisbanes/ensemble"
  license "Apache-2.0"
  # cargo-dist populates per-platform URLs + SHA256s
  # ...
  def install
    bin.install "ensemble"
  end
  test do
    assert_match "ensemble", shell_output("#{bin}/ensemble --help")
  end
end
```

### Cask: `Casks/ensemble-desktop.rb`

Updated by the Phase 3 CI job.

```ruby
cask "ensemble-desktop" do
  version "0.2.0"
  sha256 "abc123..."

  url "https://github.com/chrisbanes/ensemble/releases/download/v#{version}/Ensemble_#{version}_aarch64.dmg"
  name "Ensemble"
  desc "Multi-agent pipeline orchestrator"
  homepage "https://github.com/chrisbanes/ensemble"

  depends_on arch: :arm64

  app "Ensemble.app"
end
```

### User installation

```sh
brew install chrisbanes/tap/ensemble            # CLI
brew install --cask chrisbanes/tap/ensemble-desktop  # Desktop app
```

## GitHub Secrets Required

| Secret | Purpose |
|---|---|
| `HOMEBREW_TAP_TOKEN` | GitHub PAT with repo access to `chrisbanes/homebrew-tap` for pushing formula/cask updates |
| `APPLE_CERTIFICATE` | Base64-encoded .p12 signing certificate for macOS code signing |
| `APPLE_CERTIFICATE_PASSWORD` | Password for the .p12 certificate |
| `APPLE_ID` | Apple ID email for notarization |
| `APPLE_TEAM_ID` | Apple Developer team ID |
| `APPLE_PASSWORD` | App-specific password for notarization |

## Release Checklist (Manual Steps for First Release)

1. Install `cargo-release`: `cargo install cargo-release`
2. Run `cargo dist init` to bootstrap cargo-dist configuration
3. Configure GitHub secrets (listed above)
4. Create `Casks/` directory in `chrisbanes/homebrew-tap` if it doesn't exist
5. Run first release: `cargo release 0.1.0 --execute`
