# S01 Codex/macOS qualification: blocking termination finding

Status: **failed gate, incomplete S01**. This is a bounded investigation of the
direct App Server process-group approach, not a standalone Ensemble implementation
or product acceptance. No scheduler, database, UI, or Haze state was touched.

  (`main` before S01 evidence changes). Reviewed scope was already present from
  `40b045d6033184fb570e09a45ba5b04e1d8e8241`.
- macOS 26.7, build 25G229, arm64; user `chris` (UID 501), the current operator
  login context. `codex-cli 0.157.1` at `/opt/homebrew/bin/codex`.
- `codex login status` returned `Logged in using ChatGPT`; the App Server
  `account/read` response reported account type `chatgpt`. No credential content
  was read or copied and no API-key fallback was used. This verifies the current
  interactive user, not a future `launchd` service context or expired login.
- Protocol: experimental App Server CLI, newline-delimited JSON over `stdio://`.
  `initialize` returned platform `unix`/`macos`. The installed server accepted
  `sandbox: "workspace-write"` on `thread/start`; `"workspaceWrite"` failed with
  JSON-RPC `-32600` (unknown variant). The current [official App Server guide]
  (https://learn.chatgpt.com/docs/app-server) documents the lifecycle and a
  distinct structured `turn/start.sandboxPolicy` shape. Pin and verify the exact
  generated schema before an integration contract is finalized.

## Commands and observations

All commands ran from the workspace work directory, with a fresh `s01-fixture`
Git repository outside the Ensemble checkout. The exact tested scripts were
`s01-probe.py`, `s01-death.py`, and `s01-fixture/writer.py`; byte-for-byte copies
are included as `test/s01/probe.py`, `test/s01/death.py`, and
`test/s01/writer.py` for reproduction.
The App Server was launched as a new session by each probe. Times below are UTC;
script timestamps use Unix seconds.

```sh
mkdir -p s01-fixture && git -C s01-fixture init -q
python3 s01-probe.py s01-fixture
python3 s01-death.py s01-fixture
wc -l s01-fixture/effects.log
ps -p 61716,61730 -o pid,ppid,pgid,stat,command
```

To reproduce from a fresh workspace work directory after this run, copy the
three committed scripts from `ensemble/test/s01/` to the names above before
running the same commands. The original disposable fixture and script copies
were removed after recording the evidence.

1. `probe.py` initialized App Server, read account type, created persistent
   thread `01a0e4b5-a409-7272-9272-081d015937c2`, started one bounded turn,
   observed a completed `commandExecution` item and completed turn, read one
   stored turn, and resumed that same thread by ID. `proof.txt` contained
   `S01_OK`. The turn ran from Unix time 1790543504.579 to 1790543512.778
   (8.199 seconds). The App Server exited normally after the probe. A prior
   ephemeral thread `01a0e4b5-4fa9-7073-820f-221a066cfddf` completed its
   write, but `thread/read(includeTurns)` and `thread/resume` returned errors:
   ephemeral threads do not support stored turns or resume. Thus a durable
   thread is required for Ensemble resume.
2. `death.py` initialized a separate App Server (PID 61321, process group
   61321), started ephemeral test thread
   `01a0e4b6-bb7b-7f50-9412-ac04e7356b32` and turn
   `01a0e4b6-bc08-75a0-b851-4334f490fd9c`, then waited for a real Codex
   writing-tool effect from `writer.py`. At 2026-09-27T21:13:03Z, with effect
   log size 34 bytes, the harness sent `SIGKILL` to the App Server process
   group. The App Server exited `-9`. Its writer (PID 61716) and writer child
   (PID 61730) were still alive 1.5 seconds later; the log grew to 136 bytes
   (eight total writes). The test therefore **does not** establish active
   execution termination from killing the App Server group.
3. The harness sent `SIGKILL` to the two recorded fixture PIDs in its `finally`
   block. A subsequent `ps -p 61716,61730` showed neither process, and the
   effect log ended at eight lines. The fixture files and new test-thread
   rollouts are disposable probe artifacts; no existing session was targeted.

The death probe intentionally killed the isolated App Server group, not an
Ensemble service process or a proposed external watchdog. It proves that this
simple containment approach is insufficient for the observed Codex tool tree;
it does not prove that every macOS supervision design is impossible. The source
of the surviving process-group separation remains unmeasured.

## Gate and integration contract consequence

Do not release a writer or admit its replacement on App Server exit, a lost
connection, an interrupt acknowledgement, or a PID-only check. A separate
execution supervisor must own a termination boundary that covers Codex tool
descendants, survive or detect service death, and confirm no old writer can
continue before durable ownership is released. The supervisor design and its
macOS proof are still missing. Keep S01 open and dependent S02/S03 work held
until a concrete containment design passes the abrupt-death test, including a
writer that creates its own child/process group.

The other required S01 probes were not run after this blocking finding:
payload-spoofed coordination callbacks; startup/storage/policy failures and
pause/stop races; lost submission/binding responses and stale revisions;
stop before launch or during admission; interruption during a writing tool;
missing observations, PID reuse and acknowledged-but-unconfirmed interruption;
unavailable login; workspace escape/approval behavior; event delivery limits.
None is marked passed. The successful single-turn lifecycle is only a partial
R01 observation. There is no SQLite fixture or database result in this run.

Churchill should decide whether S01 may pursue an explicit external supervisor
or launchd containment proof, with writer ownership held until confirmed
termination. If the guarantee must change, that is a product decision rather
than an implicit fallback. At that checkpoint, the remaining
[S01 #688](https://github.com/chrisbanes/ensemble/issues/688) probes needed
their own bounded evidence before S01 could pass.
